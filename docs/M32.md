# Préparer une Midas M32

Dans **Nouveau show**, choisissez **Midas M32**. Ce profil correspond à la M32 pleine taille / M32 LIVE : 32 préamplis locaux, 16 sorties XLR, 6 entrées / sorties Aux, AES50 A et B, carte audio 32 × 32 et sortie AES/EBU. Les profils WING, WING COMPACT et WING RACK restent disponibles.

## Capacités de préparation

| Élément | Profil M32 |
| --- | --- |
| Voies principales | 32 mono ; une source stéréo occupe une paire impair/pair |
| Bus de mixage | 16 mono ; un IEM / groupe stéréo occupe deux bus liés |
| Masters | Main LR stéréo et M/C mono |
| Matrices | 6 mono, liables par paires |
| Moteurs FX | 8 stéréo, 61 algorithmes au catalogue |
| Affectations de groupe | 8 DCA et 6 mute groups ; aucune affectation par défaut |
| Préamplis | Gain de −12 à +60 dB ; phantom Local / AES50 A / B |
| Coupe-bas | Désactivé ou 20 à 400 Hz |
| Export | Scène texte `.scn`, format 4.0, destinée aux firmwares M32 4.x |

Le compteur d’entrées indique les voies DSP consommées. Le tableau garde une ligne par source : cinq lignes comprenant une paire stéréo peuvent donc consommer six voies. Une paire stéréo commence sur une voie impaire ; les outils d’insertion et de renumérotation déplacent toute la paire, ses affectations et ses cibles d’effets. Le format M/S de la WING n’est pas proposé sur la M32 : il nécessite un décodage en amont ou une préparation dans M32-Edit.

Les noms sont exportés en caractères ASCII et limités à 12 caractères sur les tranches. Les noms DCA sont saisis sur 8 caractères dans l’interface commune. Les noms personnalisés de mute groups restent dans le projet ChickenWing ; la scène M32 mémorise leurs membres et leur activation.

## Effets et envois

Les slots **FX 1–4** acceptent tous les algorithmes et peuvent travailler en insert ou avec un retour FX stéréo. Les slots **FX 5–8** proposent uniquement les modèles compatibles en insert. Le catalogue grise les choix indisponibles et l’export refuse une combinaison invalide.

Pour une réverbération en auxiliaire, choisissez **Envoi vers un retour FX**, puis ses bus source gauche / droit. Un bus mono peut alimenter les deux côtés. Les bus source qui manquent sont ajoutés au routing. Préparez le niveau, le mute et l’assignation Main LR du retour ; retrouvez ses autres envois dans **Routing & envois**. Les retours occupent les tranches natives FX 1L/R à FX 4L/R, sans consommer de voie principale.

Pour un insert, choisissez la tranche et la position avant / après EQ. La M32 possède un seul insert par tranche. Sur une paire stéréo liée, les côtés L et R de l’effet sont affectés automatiquement. Une destination supplémentaire permet d’utiliser le côté droit sur une seconde tranche mono, notamment avec les effets Dual.

Les paramètres fins des algorithmes se règlent dans M32-Edit. Lors du chargement d’un nouvel export, les changements de type d’effet initialisent le jeu de paramètres natif du modèle : aucun paramètre WING n’est copié dans un moteur M32. Les emplacements non préparés n’ont aucune affectation audio.

La matrice suit le trajet M32 : voies et retours FX vers bus / Main, bus vers Main / matrices, Main vers matrices. Les liaisons indisponibles sont désactivées. Le Main LR reçoit une assignation à 0 dB post-fader ; le niveau est commandé par le fader de la tranche. Les points de prélèvement des envois sont communs aux deux bus d’une paire : une modification synchronise la paire. Le mode Groupe utilise un départ à 0 dB.

## Routage et fichiers

L’export construit **User In** pour les entrées à l’unité, puis les blocs User Out nécessaires pour les sorties Local, AES50 et Card. Une sortie physique non préparée reste silencieuse. Les signaux et les blocs identiques sont partagés. Si le patch dépasse les 32 points Out / P16 ou les six blocs User Out distincts que ce compilateur peut représenter, l’export explique le conflit ; il ne remplace pas une source par une autre. Regroupez les adresses et réutilisez des blocs identiques pour simplifier un patch très dispersé.

1. Cliquez sur **Exporter le show → Scène M32** pour télécharger le `.scn`.
2. Dans M32-Edit, utilisez **Load → Load scene** pour ouvrir ce fichier. Vérifiez les sources, les gains / phantom, les envois, les inserts et les sorties.
3. Pour la console, copiez le `.scn` sur une clé USB et importez-le depuis la gestion des scènes. Le profil vise les firmwares 4.x qui disposent de User In / User Out.
4. Conservez aussi le **Projet ChickenWing** `.json`. Il garde les références microphones, les groupes de couleur, les règles de conversion DCA et les snapshots de travail.

Un show conserve sa famille de console. Pour passer d’une préparation WING à la M32, créez un show M32 et utilisez votre patch / fiche technique ; les traitements propres à la WING ne sont pas convertis automatiquement. Les `.scn` sont exportés ; l’import direct d’une scène M32 dans ChickenWing n’est pas proposé dans cette version. Les imports de fiches techniques et les projets ChickenWing restent disponibles. Un patch importé doit respecter les numéros et paires de la console sélectionnée ; les conflits sont signalés avant export.

L’éditeur principal prépare les 32 voies. Les tranches Aux / USB sont accessibles aux affectations DCA / mute ; leur traitement détaillé se prépare dans M32-Edit. Les réglages globaux non proposés dans ChickenWing, tels que les préférences de surface, l’horloge ou le monitoring, se vérifient dans l’éditeur natif / sur la console.

## Vérification et références

Une scène réellement téléchargée depuis l’application a été chargée puis réenregistrée dans **M32-Edit 4.3 sur ce Mac**, hors connexion. Les tables User In / Out, les blocs Local / AES50 / Card, les paires de voies et de bus, le phantom Local et AES50 B 47–48, les gains, les masques DCA / mute, le départ FX, les deux côtés d’un insert et l’envoi Main LR vers matrice ont été comparés au fichier réenregistré. Les écarts numériques observés sur les points vérifiés se limitent à leur présentation (`+0` / `0`, par exemple). Les plages de fréquence peuvent être arrondies à la résolution native.

Aucun essai sur une M32 physique n’a été réalisé. La vérification dans M32-Edit ne remplace pas le contrôle avant rappel en prestation.
